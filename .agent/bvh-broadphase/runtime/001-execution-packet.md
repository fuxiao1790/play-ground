## Relevant Global Context
(Condensed from `implementation-context.md`; read that file for more if
needed.)

- No `unsafe` anywhere. `PlayGround.Sim.asmdef.allowUnsafeCode=false` and
  `ProjectSettings/ProjectSettings.asset: allowUnsafeCode: 0` — both must stay
  false. No pointers, no `fixed` buffers, no `NativeList<T>` per query.
- `BvhConfig.ChildCount` is `4` or `8`, compile-time only. It alone must
  determine children-per-node, bound storage, reference/kind storage,
  active-mask width, grouping size, traversal loop bound, and validation loop
  bound — do not scatter literal `4`/`8` elsewhere.
- BVH4 node test: three `float4` values (X, Y, radius). Full overlap equation
  (subtract, multiply, add, compare, extract) executes as one packed
  operation ending in `math.bitmask` (or an equivalent single packed mask
  extraction) — no scalar per-lane arithmetic/compare/`if` before the mask
  exists.
- BVH8 node test: three `Unity.Burst.Intrinsics.v256` values, full AVX
  equation (subtract/multiply/add/compare/movemask), used only where
  `Unity.Burst.Intrinsics.X86.Avx.IsAvxSupported` — this is the standard Burst
  ISA-branch idiom (Burst specializes both branches; only the supported one
  executes at runtime). Portable (non-AVX) BVH8 fallback: two complete
  `float4` overlap tests, each producing its own 4-bit mask, combined into one
  8-bit result — never an 8-lane scalar loop.
- Traversal is scalar from the moment the packed mask exists: extract set
  bits, read child kind/reference metadata (only after the mask says a lane is
  worth reading), push node children onto a fixed-capacity stack, or run
  against the child object index for object children. The tree itself does
  not run narrowphase — it only yields snapshot/object indices (task 001 has
  no ECS snapshot yet, so it yields whatever integer index the caller supplied
  for that circle at build time).
- No duplicate object array: the builder takes exactly one input array of
  circles (center + radius), indexed 0..N-1 by the caller; that same index is
  what leaf children reference. Do not invent a second "BroadphaseObject"
  record with entity/shape fields — that's explicitly out of scope (the real
  entity/shape data lives in the target snapshot introduced in task 002).
- Traversal workspace is one fixed-capacity struct
  (`FixedList512Bytes<int>`-based) that is reset/reseeded per query, not
  allocated per query. It must stream results via something like
  `TryMoveNext(out int objectIndex)` rather than collecting into one bounded
  list that could overflow past 127 objects for one query — the workspace
  itself (the traversal stack) is bounded by proven tree depth × width, but
  the *candidate output* must not be a fixed collection that silently drops
  results when a query overlaps more than the collection's capacity.
- Full rebuild every call (no refit, no double buffering, no persistence
  concerns yet — task 001's build API is a pure function the tests call
  directly with their own `NativeArray` inputs. Persistent-owner integration
  is task 002's job).
- Root is an internal node whenever there is at least one object (objects
  placed directly into the root's child lanes when count ≤ `ChildCount`); an
  empty input produces `RootNodeIndex = -1` and queries against it must
  short-circuit safely (no exception, no stack push).
- Unused lanes: `BvhChildKind.Unused`, excluded via an explicit active-lane
  bitmask (`mask &= activeMask` after the geometric test, before scalar
  dispatch) — never rely on radius tricks alone.
- Squared-distance comparisons only; never `sqrt` in the overlap test. Small
  fixed epsilon added to the combined-radius-squared comparison to avoid
  floating-point false negatives at exact contact.
- Broadphase must return zero false negatives; false positives are fine and
  expected (that's the whole reason exact narrowphase still runs downstream —
  though task 001 itself does not call any narrowphase, since it has no real
  shapes; its tests validate against brute-force circle-circle overlap of the
  same conservative circles used to build the tree).

## Step-By-Step Instructions
1. Add `BvhConfig.ChildCount` (default `8`) and fail-fast validation that
   rejects any other compile-time value clearly (a `static readonly`/const
   guard checked once, e.g. at first tree build or via a `[BurstDiscard]`
   editor-time assert — pick whatever the codebase's existing "fail fast"
   convention supports in Burst-compiled code; document the chosen mechanism
   briefly in a one-line comment only if the reason is non-obvious).
2. Define `BvhChildKind` (`Unused = 0, Node = 1, Object = 2`), a circle struct,
   a Morton-entry struct (Morton key + original object index).
3. Define separate concrete BVH4 and BVH8 node representations (hot
   bounds/cold metadata split per `bvh.md` §36). Metadata (child reference,
   child kind, active mask) must not require `fixed` buffers or `unsafe` —
   use plain fields (e.g. `Reference0..Reference3` for BVH4,
   `Reference0..Reference7` for BVH8) or flattened persistent
   `NativeArray<int>`/`NativeArray<byte>` addressed as
   `nodeIndex * ChildCount + lane`, whichever keeps the packed hot-bounds load
   contiguous and gather-free. Only one of BVH4/BVH8 is compiled in per
   `BvhConfig.ChildCount`; do not build both.
4. Implement the deterministic builder: normalize object centers into build
   bounds, quantize/interleave into a Morton key, sort `(key, index)` pairs
   with index as tiebreaker, group bottom-up into node lanes of at most
   `ChildCount`, build each parent circle as AABB-center + max
   `distance(center, childCenter) + childRadius` (bvh.md §22), repeat until
   one root remains. Handle 0, 1..ChildCount-1, and exact-multiple counts.
5. Implement the BVH4 SIMD node test using `float4` end-to-end (subtract,
   multiply, add vs combined-radius-squared, compare, `math.bitmask`).
6. Implement the BVH8 SIMD node test: an `Avx.IsAvxSupported`-guarded branch
   using `v256` AVX intrinsics end-to-end (subtract/multiply/add/compare/
   `mm256_movemask_ps`), and a portable fallback branch that runs the BVH4-style
   `float4` test twice (once per 4-lane half) and combines the two 4-bit masks
   into one 8-bit mask. Both branches must be real, compiled, reachable code —
   not one stubbed out.
7. Implement scalar traversal: fixed-capacity stack sized from a documented
   depth/width bound, pop node, run the node's width-selected SIMD test,
   `mask &= activeMask`, then while `mask != 0`: extract lowest set bit,
   inspect that lane's kind/reference, push (node) or yield (object), clear
   the bit. Expose it as a resettable workspace with `Reset(query)` +
   `TryMoveNext(out int objectIndex)` so callers (and tests) can stream
   results without a bounded output collection.
8. Implement validation helpers usable from tests: given a built tree, recurse
   from the root and assert every parent circle contains every descendant
   object/node circle within a small epsilon; assert every referenced lane is
   within `[0, ChildCount)` and active; assert the stack capacity used during
   traversal never would have overflowed for the tree's actual depth.
9. Write `BvhBroadphaseEditModeTests` covering (see Acceptance Criteria below
   for the exhaustive list) — build determinism, containment, mask
   correctness at both widths, unsupported-width failure, empty/degenerate
   scenes, workspace streaming past 127 objects in one query, and randomized
   brute-force cross-check (every brute-force circle-circle overlap the BVH
   must also return; extra false positives are fine).
10. Self-review the two node-test kernels specifically for the forbidden
    pattern: any scalar loop or `if` touching individual lanes before the
    packed mask is produced. This is the single most likely way to silently
    fail the plan's core requirement even though the code "looks right" and
    compiles.

## Acceptance Criteria
(Copied from `001-safe-wide-bvh-core.md` — all must hold.)
- Changing only `BvhConfig.ChildCount` between 4 and 8 selects matching
  physical node size and query/build path after recompilation.
- BVH4 source expresses complete overlap math as packed `float4` operations
  and obtains all four results through one packed mask extraction; no scalar
  per-lane comparison/branch occurs before mask production.
- BVH8 AVX source expresses complete overlap math through packed AVX
  subtract/multiply/add/compare/movemask operations. Partial AVX followed by
  scalar lane math does not pass.
- BVH8 fallback performs two complete packed `float4` tests and combines their
  masks; it does not loop over eight scalar lanes.
- Traversal remains scalar only after node kernel returns lane mask: set-bit
  extraction, child metadata lookup, stack push, and leaf yield.
- Unsupported width fails clearly during owner system creation (there is no
  owner system yet in this task — implement the guard so it is ready to be
  invoked from task 002's system creation; a static validation method callable
  at that point is sufficient).
- Empty, partial-root, multi-level, equal-position, negative-coordinate, and
  zero-extent scenes build deterministically.
- All unused lanes remain masked and carry `Unused` kind.
- Every parent child-circle contains referenced object/node circle within
  chosen epsilon.
- Fixed stack capacity is proven sufficient for built tree before publication.
- Workspace reset changes logical stack/mask/query state only; it does not
  clear or copy all 512 bytes between entities.
- Traversal streams leaves through `TryMoveNext`; no fixed candidate
  collection can overflow when more than 127 objects overlap one query.
- Core API supports discrete projectile source-bound circles. Acceptance does
  not require elongated continuous sweep-box queries or any other consumer.
- Randomized circle queries return every brute-force exact overlap; false
  positives allowed.
- Rectangle/capsule object and source bounding circles cannot prune exact
  hits (i.e. the conservative-circle construction never shrinks below the
  true shape).
- New EditMode class `BvhBroadphaseEditModeTests` covers above contracts
  without asserting private memory implementation beyond configured width and
  public diagnostics.
- `PlayGround.Sim.asmdef` and project `allowUnsafeCode` remain false (do not
  touch these files — verify by inspection only).
